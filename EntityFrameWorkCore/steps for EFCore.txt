EFCORE************************************************************************************

What are Data Models in EF Core?
In Entity Framework Core (EF Core), a data model describes how your application's C# classes and properties are mapped to a database's tables and columns.

EF Core uses this model to read and save data, understand relationships between tables, and generate database changes through migrations. 

Microsoft Learn
+1




Think of it this way:
- C# class = describes an entity, such as a student.
- Properties = describe the entity's data, such as name and age.
- EF Core model = describes how that data is represented in the database.
- Database table = stores the actual records.


*********************************DbContext in Entity Framework Core
What is DbContext?

DbContext is the central class in Entity Framework Core (EF Core). It acts as a bridge between your C# code and the database. You use it to:

Connect to the database
Query data (read)
Save changes (insert, update, delete)
Track changes made to objects
Define how your classes map to tables

************************************************Database Support: Connection Strings in EF Core

This slide is about where and how you tell EF Core which database to connect to. It builds directly on the OnConfiguring method from your previous slide.

What is a connection string?

A connection string is a line of text that tells your app how to reach the database: the server, the database name, and how to log in.

Server=localhost;Database=FootballLeague;Trusted_Connection=True;TrustServerCertificate=True;
Point 1: “Connection string is used during instantiation and in OnConfiguring by default”

When your DbContext is created (instantiated), EF Core needs to know which database to use. By default, that information is supplied through the context’s configuration, and OnConfiguring is the method where the final options get applied.

Point 2: “Can be configured manually in OnConfiguring (not recommended)”

This is the approach from the previous slide, where you hardcode the connection string inside the context class:

csharp
protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
{
    optionsBuilder.UseSqlServer("Server=localhost;Database=FootballLeague;Trusted_Connection=True;");
}


**************************************************IoC (Inversion of Control)
The simple idea

Normally, a class creates the things it needs by itself. With IoC, the class doesn’t create them. Something else hands them in.

“Control” over creating objects is inverted: it moves from your class to an outside system (the IoC container).

**********************************************Migrations in EF Core
The simple idea

Your C# classes (entities) and your database tables need to stay in sync. A migration is a file that records a change to your database structure (schema) so EF Core can apply it for you.

Think of migrations as version control (like Git) for your database. Each migration is a snapshot of a change: “added Teams table”, “added Coach column”, and so on.

*****EFCORE compares the current database with the snapshot of older version or model and then generates the migration file with the new changes list that has to be made on database
Using this process we can reverse the steps if we face any problem so tacking of every migration helps us.




**********************************IMPORTANT: EF Core 9.0 Migration Errors
Starting with EF Core 9.0, an exception is thrown when you attempt to apply migrations if there are pending model changes not encapsulated in a migration. The exception message typically states:

"The model for context 'DbContext' has pending changes. Add a new migration before updating the database."

Scenario: The model appears unmodified, but EF Core detects changes due to non-deterministic factors, such as using new DateTime(), DateTime.Now, DateTime.UtcNow, or Guid.NewGuid() in HasData() methods (or seeding).



Solution: Create a new migration and inspect its contents to identify the cause. Replace dynamic data with static, hardcoded values in the model. Like using a set date value instead of DateTime.Now.

After making these adjustments, recreate the migration. If dynamic data is essential for seeding, consider using alternative patterns instead of HasData().
